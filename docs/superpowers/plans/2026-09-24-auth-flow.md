# Auth Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hand-built session auth: register, login, logout, and an `auth`-protected dashboard, all covered by feature tests.

**Architecture:** Two resourceful controllers under `app/Http/Controllers/Auth/` — `RegisteredUserController` (create/store) and `SessionController` (create/store/destroy). Routes split into `guest` and `auth` middleware groups in `routes/web.php`. Blade views share one anonymous component `<x-layout>`.

**Tech Stack:** Laravel 13, Blade, Tailwind 4 (via Vite), PHPUnit 12, in-memory SQLite for tests.

**Spec:** `docs/superpowers/specs/2026-09-24-auth-flow-design.md`

## Global Constraints

- Use the existing `users` table and `User` model unchanged (`#[Fillable(['name', 'email', 'password'])]`, `'password' => 'hashed'` cast — never call `Hash::make` manually).
- Route names: `register`, `login`, `dashboard`, `logout`. The `login` name is required by the `auth` middleware.
- Logout is `POST` only.
- Every form includes `@csrf`. Password inputs never repopulate with `old()`.
- Failed-login message, exact text: `These credentials do not match our records.` — attached to the `email` field.
- Session is regenerated on login and register; invalidated + token regenerated on logout.
- Every feature test class uses `RefreshDatabase`.
- Emails are stored and compared lowercase (see Review Focus).
- No git repo in this project: skip commit steps (or run `git init` first if you want them).

## Review Focus

1. **Email case** — registering `Mario@Example.com` then logging in with `mario@example.com` should work. SQLite compares case-sensitively (MySQL doesn't), so emails are lowercased before save and before `Auth::attempt`. Tests in Task 1 and Task 3.
2. **HTML in a user's name** — a name like `<script>alert(1)</script>` must render escaped on the dashboard and nav, never as raw HTML. Test in Task 3.
3. **`GET /logout`** — typing the URL or clicking a link must not log the user out; expect 405. Test in Task 2.
4. **Failed login input** — after a wrong password the email field is refilled but the password is not flashed to the session. Test in Task 1.
5. **Logged-in user opening `/register`** — redirected to `/dashboard`, not shown the form. Test in Task 3.

- [ ] **Step 7: Create `SessionController` (create + store)**

Create `app/Http/Controllers/Auth/SessionController.php`:

```php
<?php

namespace App\Http\Controllers\Auth;

use App\Http\Controllers\Controller;
use Illuminate\Http\RedirectResponse;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Auth;
use Illuminate\Support\Str;
use Illuminate\Validation\ValidationException;
use Illuminate\View\View;

class SessionController extends Controller
{
    public function create(): View
    {
        return view('auth.login');
    }

    public function store(Request $request): RedirectResponse
    {
        $credentials = $request->validate([
            'email' => ['required', 'email'],
            'password' => ['required'],
        ]);

        $credentials['email'] = Str::lower($credentials['email']);

        if (! Auth::attempt($credentials)) {
            throw ValidationException::withMessages([
                'email' => 'These credentials do not match our records.',
            ]);
        }

        $request->session()->regenerate();

        return redirect()->intended(route('dashboard'));
    }
}
```

class RegistrationTest extends TestCase

    {

            'name' => 'Mario Rossi',

            ->assertRedirect('/dashboard');

        $this->assertNotNull($user);
        $this->assertSame('Mario Rossi', $user->name);
        $this->assertTrue(Hash::check('secret-password', $user->password));

- [ ] **Step 3: Create `RegisteredUserController`**

Create `app/Http/Controllers/Auth/RegisteredUserController.php`:

```php
<?php

namespace App\Http\Controllers\Auth;

use App\Http\Controllers\Controller;
use App\Models\User;
use Illuminate\Http\RedirectResponse;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Auth;
use Illuminate\Support\Str;
use Illuminate\View\View;

class RegisteredUserController extends Controller
{
    public function create(): View
    {
        return view('auth.register');
    }

    public function store(Request $request): RedirectResponse
    {
        $request->merge(['email' => Str::lower((string) $request->input('email'))]);

        $validated = $request->validate([
            'name' => ['required', 'string', 'max:255'],
            'email' => ['required', 'string', 'email', 'max:255', 'unique:users'],
            'password' => ['required', 'string', 'min:8', 'confirmed'],
        ]);

        $user = User::create($validated);

        Auth::login($user);

        $request->session()->regenerate();

        return redirect()->route('dashboard');
    }
}
```

The email is lowercased before validation so the `unique:users` check also catches `Mario@example.com` vs `mario@example.com`.
